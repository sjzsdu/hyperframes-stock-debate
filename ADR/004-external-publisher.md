# ADR-004 · 将现有 SAU 外置为可选运行时

状态：提案，V6 以保全现有能力为设计准则，实测随 S3/S5。

## 背景

Publisher 已经通过 argv 调用独立进程，平台规格覆盖六个平台（stocktalk/modules/publisher.py:1-23、stocktalk/modules/publisher.py:269-293）。发布工具解析与运行依赖路径和 cwd（stocktalk/modules/publisher.py:760-761、stocktalk/modules/publisher.py:1455-1493）。登录态引用依赖根目录（stocktalk/modules/publisher.py:1204、stocktalk/modules/publisher.py:1333）。基线树有 15 个 patch 文件，README 的重放清单有 14 条，`0009` 保留在树中但未列入现有重放步骤。`conf.py` 随基线树归档（third_party/README.md:216-237、third_party/README.md:248-255、third_party/README.md:272-278）。初始迁移因此以当前有效 vendor 树为行为基线。

## 备选方案与理由

| 方案 | 取舍 |
| --- | --- |
| 保留整包 vendor 并将安装改为可选 | 迁移最短，仓库仍承担整树和 patch 维护 |
| 直接安装上游发布物 | 维护低，现有补丁覆盖的登录及上传行为未验证 |
| 固定外置已验证版本，沿用子进程接口 | 复用当前行为并能退回；增加一次外置安装与版本管理 |
| 自建发布服务 | 可隔离故障，需维护协议、账号存储、部署和对账 |

## 决策

采用第三项。生成/管理无需安装 SAU，发布预检提供可操作的缺依赖结果。保持 Publisher 已有 argv、平台规格、登录检查、输出解析、交互守卫与超时。新配置提供 `publish.sau_executable` 和 `publish.sau_dir` 两个非秘密路径，显式可执行路径优先；保留已有 `sau_dir/.venv/bin/sau` 和 `PATH` 的兼容解析。平台模式配置为外置绝对路径，禁止 UI 提交任意命令或路径；CLI 支持原配置。派生 cwd 和 cookie 路径必须来自同一版本根，避免交叉读取账号。通过版本与工具健康预检报告能力。CLI、守护任务和平台用例须共同经过 Publisher，在用户级私有目录按平台与实际账号加进程锁，持有到发布子进程退出。锁争用时报告账号忙。

## 迁移步骤与验证

1. 保留可运行的旧 CLI 和原运行目录。先在无账号的目录从基线 Git 树生成外置归档，排除本机 cookie、venv、日志和真实配置。命令可用 `git archive --format=tar --prefix=sau/ e9cddcc:third_party/social-auto-upload` 取得纯跟踪快照，再核对跟踪清单和秘密扫描。核实上游许可并保留许可、来源 SHA、归档 SHA256、依赖锁与安装说明。用快照外置发行物做首次迁移，现有补丁留作审计，增量为 0。
2. 从归档安装到独立的私有版本目录，用 `uv sync --locked` 安装依赖（先验证锁与当前 Python 可用）。按现有发布预检安装或校验浏览器。在新根用独立的本机账号数据目录；已有 Cookie 在原路径保留，通过仅拥有者可读的本机路径迁移或重新登录。迁移数据排除配置文档、日志和发行物，测试只用无密钥夹具。
3. 先合入解析兼容与替身测试。六平台逐项比较旧/新 argv、账户和 cwd、画幅、定时、AI 声明与登录预检，覆盖成功、失败和阻塞提示。对相同输入跑一次固定沙箱，比较标准化输出与逐平台报告。若有不一致，维持原路径并修正兼容桥。发起真实发布前，掌握账号的运营者仍需验证真实平台自身的现行行为。
4. 升级时先停同账号守护任务或排空相关队列，将工具根与可执行文件作为同一次配置变更切到外置版本。核对启动、预检、固定夹具和旧 CLI，随后移出主仓整树。保留基线归档和可恢复的旧路径。以 `pytest -q`、大小/文件数、patch 计数与回退实录交付 AC-05。今后若要从上游重建，先核对 `0009` 是否已体现于基线树，以及 `conf.py` 差异和行为，兼容问题优先修主仓适配层或向上游贡献，主仓不新增本地补丁。

保全基线包括六个平台的适配能力、现有默认平台配置和账号命名、多画幅、封面、AI 声明、定时、预检、逐平台报告、补发及人工挑战路径。旧 CLI 的调用参数与交互保留。Web 遇到扫码或 SMS 等人工挑战，返回需要本机操作的明确结果，操作者完成后按远端结果核对再决定重试。

## 成本、风险与回退

估算 2–4 人日，固定费用为 0，无常驻新服务，每次发布沿用子进程。风险来自浏览器版本、账号路径和外部平台更新。回退时先停止领取发布、等待或标记未知结果，再把可执行文件与根路径一同指向上一个已验证的外置目录，或还原旧 CLI 与原工具树。复跑登录预检与固定沙箱，核对结果合同后恢复。已确认成功的记录禁止重投，未知结果走人工核对。保留归档和锁文件便于转让和重建。省略外置步骤会继续维护整包 vendor。
